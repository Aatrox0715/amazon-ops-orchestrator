## 目标

产出**可直接粘贴进后台**的四段文案：标题 / 商品亮点 / 五点 / 后台 Search Terms。

## 输入要求

| 输入 | 必需 | 缺失时怎么办 |
|---|---|---|
| **词位置映射** | **是** | 从环节 04 的 `word_placement` 读。**不要自己重新分配** —— 那是环节 04 已过闸门的决策 |
| 竞品文案结构 | 推荐 | 从环节 02 读，用于对照结构（但**不照抄排序**） |

| 产品事实 | **是** | 只能写 listing 已披露事实能支撑的内容，**不得编造产品特性** |

## 硬约束（2026-07-27 新规，S1 级）

| 位置 | 限制 | 来源 |
|---|---|---|
| **标题** | **≤ 75 字符**（含空格），全品类除媒体类 | f001 / f087（GYTR6SYGFA5E3EQC） |
| **商品亮点 Item Highlights** | **≤ 125 字符**，逗号分隔短语（非整句）；**仅标题 <75 字符时展示，且可被搜索索引** | f088 |
| **五点 Bullets** | 每条 **10–255 字符**，共 5 条；总字节 ≤1000 才完整索引 | f003（GX5L8BF8GLMML6CX） |
| **后台 Search Terms** | 美国站 **≤ 250 bytes**；超限可能整字段不被索引 | f0xx（Search Terms 卡） |

**禁用项**：

- **字符**：`! $ ? _ { } ^ ¬ ¦`（品牌名内部允许）
- **同词重复不超 2 次**（介词、冠词、连词除外）
- **主观 / 比较声明**：如「最受欢迎」「环保」「抗微生物」
- **保证类话术**：如「全额退款」
- ASIN 代码、外部链接
- 表情符号、占位文字（N/A、TBD）

⚠️ **引用前查 `reviewDueAt`**。标题规范卡为 `volatile=true`，6 个月复核一次。当前核实 2026-09，未过期。

## 执行步骤

### 第 1 步 · 读上游的词位置映射

从环节 04 的 `word_placement` 读：
- 标题放哪些词（核心 + 最强属性）
- 商品亮点放哪些
- 五点放哪些
- 后台 Search Terms 放哪些

**不要自己重新分配** —— 那是环节 04 已经做过并通过 P1 闸门确认的决策。

### 第 2 步 · 标题撰写

**字符预算分配**：75 字符是很紧张的预算，要先决定"品牌名占不占位"。

| 策略 | 优点 | 代价 |
|---|---|---|
| **品牌前置** | 品牌曝光、复购识别 | 占用 8–10 字符，挤压关键词位 |
| **关键词优先（无品牌）** | 全部字符给关键词，覆盖最大化 | 无品牌识别；与对手策略相同 |

⚠️ 注意：**对手的标题里没有品牌名**（173 字符全给关键词）。这是它的选择，不是标准答案。

### 第 3 步 · 商品亮点

逗号分隔的**短语**，不是整句。承接标题放不下的属性与场景词。

因为该字段**仅在标题 <75 字符时才展示**，所以它实际上是"标题溢出信息的合法容器"。

### 第 4 步 · 五点 —— **关键：排序依据来自 VOC，不是照抄对手**

对手的五点顺序（设计→材质→适配→场景→情感）是一种选择，**不是标准答案**。

本环节必须用环节 03 的 VOC 数据决定排序：

- **100% 正面的维度前移**（在对手那里被排在后位的，可能是被低估的资产）
- **负面率高的维度不占首位**，且措辞上**避免强化该方向的疑虑**
- 每条用「标题 + 冒号 + 描述」写法，结尾不加句号

### 第 5 步 · 后台 Search Terms

放长尾词层全部 + 未入选标题的属性词。控制在 250 bytes 内，**不要为塞满而堆砌不相关词**（会稀释相关性）。

### 第 6 步 · 合规自检（必做）

用 `scripts/listing_check.py` 逐项校验：字符数 / 禁用字符 / 同词重复 / 禁用话术。

**自检不通过不许进 P1 闸门。**

### 第 7 步 · ⛔ P1 闸门

见下方「P1 闸门的方案维度」。

## 两条不能破的原则

### 1. 不得编造产品特性

只写 **listing 已有事实能支撑**的内容。

**反例**：看到 VOC 显示有卡扣问题，就写 `reinforced clasp`（加固扣件）——**但并不知道产品实际是否加固了**。这是编造。

**正解**：如果无法解决该问题（属产品端），文案侧能做的只是**避免强化易损预期**，而不是虚构一个解决方案。

### 2. 买家用词优先于卖家臆想词

环节 03 提取的 `buyer_language` 是买家原文用词，比卖家自造的形容词更有效。优先级：**买家原词 > 类目惯用词 > 自创词**。

## P1 闸门的方案维度

| 维度 | 选项 |
|---|---|
| **标题策略** | 品牌前置 / 关键词优先（无品牌）/ 品牌后置 |
| **五点排序** | VOC 导向（证据强度排序）/ 对手结构（设计优先）/ 混合 |
| **对风险维度的处理尺度** | 完全回避 / 淡化措辞 / 正面重构 |
| **商品亮点是否使用** | 使用（需标题留出余量）/ 不使用 |

## output.json 的 payload 契约

```json
{
  "asin": "",
  "data_path": "L2",
  "title": { "text": "", "char_count": 0, "limit": 75, "brand_in_title": true },
  "item_highlights": { "text": "", "char_count": 0, "limit": 125, "used": true },
  "bullets": [
    { "order": 1, "head": "", "text": "", "char_count": 0, "voc_basis": "依据哪个维度的数据" }
  ],
  "search_terms": { "text": "", "byte_count": 0, "limit_bytes": 250 },
  "compliance_check": {
    "passed": true,
    "issues": [],
    "checked_at": ""
  },
  "strategy_options": [],
  "selected_strategy": null
}
```

`selected_strategy` 在用户选定前**必须保持 null**。

## 已知局限

1. **无搜索量数据** → 无法判断哪个词更值得占标题的稀缺字符位（环节 04 的遗留约束）
2. **后台 Search Terms 无法验证** → 只能按规范控制字节数，无法知道对手实际填了什么
3. **文案效果需实测** → 转化率要上架后才见分晓（属环节 10 复盘）
4. **A+ 内容不在本环节** → 属环节 07 视觉素材规划
