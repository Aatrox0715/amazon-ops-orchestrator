## ⚠️ 硬前提：本环节必须有实际数据

**这是唯一一个「没有数据就只能产出框架」的环节。**

复盘的本质是**用真实结果检验前面的判断**。没有数据时的"复盘"只能是空谈或编造，两者都不做。

**数据来源**（任一）：
- 后台 Business Reports（销量、Session、转化率）
- 广告后台（ACoS、TACoS、搜索词报告）
- 卖家自己的运营数据表

**没有数据时的正确做法**：
1. 产出**复盘方法论 + 可填模板**
2. 做**假设性推演**（"若数据显示 X，则应回改哪个环节"）—— 明确标注为推演，不是结论
3. **不写任何"复盘结论"**

---

## 目标

两件事：

1. **用实际数据检验前面各环节的判断**（哪些判断被验证、哪些被推翻）
2. **把复盘结论回写到对应环节**（形成闭环，这是整条流程的价值所在）

---

## 复盘看什么

| 维度 | 指标 | 检验什么 |
|---|---|---|
| **流量** | Sessions、Session % | 标题/词库的关键词覆盖是否有效（环节 04/06） |
| **转化** | CVR、Unit Session % | 文案与视觉的说服力（环节 06/07） |
| **广告** | ACoS、TACoS、搜索词 | 词库分层与架构是否合理（环节 04/09） |
| **利润** | 实际毛利 vs 测算 | 成本假设是否准确（环节 05） |
| **口碑** | 评论星级变化、新评论关键词 | VOC 判断是否仍然成立（环节 03） |

---

## 迭代回写机制（闭环的关键）

复盘结论**不能只写在新文件里**，必须显式标注「要回写哪一环的哪个字段」。

```json
{
  "iteration_targets": [
    {
      "stage": "06",
      "field": "title",
      "action": "replace",
      "reason": "广告搜索词显示 X 词的转化率高，但标题未覆盖",
      "evidence": "搜索词报告：X 词 30 天 12 单，ACoS 18%",
      "priority": "高"
    }
  ]
}
```

回写流程：

```
复盘发现 → 列出 iteration_targets → 用户批准 → 回到对应环节执行修改
→ 在 _state.json 的 revision_history 记一笔（原版保留）
```

⚠️ **本节改动旧产出物时，原版本要保留**（改名 `report.v2.md`），不能覆盖 —— 历史判断本身有复盘价值。

## 执行步骤

### 第 1 步 · 取数

从后台导出：业务报告（Sessions/CVR）+ 广告报告（ACoS/搜索词）+ 库存报告。

**取数区间**：至少覆盖一个完整的广告优化周期（建议 14 天以上），否则波动大于信号。

### 第 2 步 · 逐维度对照

把实际数据与前面各环节的**预测/判断**逐条对照：

| 环节 | 当时的判断 | 实际结果 | 验证 |
|---|---|---|---|
| 04 | 部分词层证据强 | ？ | 待数据 |
| 05 | 成本上限 $X | 实际成本 ？ | 待数据 |
| 06 | 五点按 VOC 排序 | 转化率 ？ | 待数据 |

### 第 3 步 · 找偏差原因

偏差比一致更有价值。重点看：
- 哪些判断**错了**（假设不成立）
- 哪些判断**对但不够**（方向对、力度不足）
- 哪些**完全没预见到**（新增变量）

### 第 4 步 · 生成迭代清单

按优先级排列，每条必须能追溯到具体环节和字段。

## output.json 的 payload 契约

```json
{
  "asin": "",
  "data_path": "L1 | L3",
  "data_availability": {
    "has_real_data": false,
    "reason": "无实际投放数据",
    "fallback": "产出方法论与模板，不做结论"
  },
  "review_dimensions": [
    { "dimension": "流量", "metrics": [], "actual": null, "vs_prediction": null, "verdict": "待数据" }
  ],
  "iteration_targets": [],
  "hypothetical_iterations": [
    { "if_data_shows": "", "then_rewrite": "stage/field", "because": "" }
  ],
  "revision_history": [],
  "strategy_options": [],
  "selected_strategy": null
}
```

⚠️ `iteration_targets` 在**没有实际数据时必须为空数组** —— 不能填推演结果。

## 已知局限

1. **必须要有实际数据** —— 这是唯一无法用 L2 反推替代的环节
2. **单次复盘价值有限** —— 至少两个周期的对比才能区分趋势与波动
3. **归因困难** —— 多因素同时变动时（改文案 + 改广告 + 季节变化），很难定位单一原因
4. **本环节是流程闭环的关键**，但也是**唯一不能"先做完再说"的环节**
