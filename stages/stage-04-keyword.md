# 环节 04 · 关键词库搭建

**闸门**：🟡 **P1（必须停下给方案让用户选，不得自行定稿）**
**目录**：`projects/<代号>/04-关键词库/`
**上游**：02 竞品拆解、03 评论与 VOC 分析
**下游**：06 Listing 文案、09 广告架构

---

## 目标

产出**可直接使用的分层词表**，回答三件事：

1. 主攻哪些词（放标题前部、重点投放）
2. 长尾怎么铺（覆盖意图更具体的搜索）
3. 哪些词要否定（避免浪费预算）

---

## 输入要求

| 输入 | 必需 | 缺失时怎么办 |
|---|---|---|
| 目标 ASIN / 产品 | 是 | 从 02 的 `output.json` 读 |
| 竞品 listing 文案 | 推荐 | 从 02 读 |
| 买家评论用词 | 推荐 | 从 03 的 `buyer_language` 读 |
| 工具导出的词表 | 可选 | **没有也能做，走 L2 反推** |
| 搜索量 / 竞争度数据 | 可选 | 标 L3，改用相对分层 |

---

## 数据源三级降级

| 级别 | 条件 | 得到什么 |
|---|---|---|
| **L1** | 有工具账号（卖家精灵 / LinkFox / 西柚等） | 完整词表：搜索量、竞争度、转化、竞价 |
| **L2** ⭐ | 无账号 | **公开反推**（主力路径，见下） |
| **L3** | 连反推都缺 | 只有少量词，分析价值有限 |

### L2 反推的四个来源（按可靠性排序）

1. **Amazon autocomplete 扩展** —— 种子词 → 搜索框下拉建议。反映真实热门搜索，最接近用户实际输入
2. **竞品 listing 反推** —— 从标题 + 五点 + 变体名提取可索引词（来自环节 02）
3. **买家评论用词** —— 买家自己的表达（来自环节 03 的语言库），比卖家臆想的词更有效
4. **类目 Top 商品名共性词** —— 多个头部 listing 都出现的词 = 类目必要词

⚠️ **L2 的固有限制**：拿不到搜索量、竞争度、转化率。因此分层只能是**相对分层**（意图清晰度 + 覆盖广度），不是按真实搜索量排序。**必须在报告显式说明这一点。**

## 执行步骤

### 第 1 步 · 确定种子词

种子词来源：产品核心品类词 + 主要属性 + 主要场景。数量 3–6 个为宜，过多会摊薄扩展质量。

### 第 2 步 · 扩展候选词

- 每个种子词跑 autocomplete，收集下拉建议
- 从 02 的 `covered_keywords_from_frontend` 并入
- 从 03 的 `buyer_language`（价值词/场景词/情感词）并入
- 去重、清洗（去品牌词、去不相关词）

### 第 3 步 · 分层

| 层 | 定义 | 用途 |
|---|---|---|
| **核心词** | 意图最明确、最贴近品类主词 | 标题前部、主攻投放 |
| **属性词** | 材质 / 规格 / 颜色 / 尺寸 | 五点、后台 Search Terms |
| **场景词** | 使用场景 / 受众 / 场合 | 五点、A+ 内容 |
| **长尾词** | 3 词以上组合、意图具体 | 广告长尾、Search Terms |
| **品牌词** | 本品 / 竞品 | 本品主攻 / 竞品截流（注意边界） |
| **否定词** | 不相关、易浪费预算 | 广告否定投放 |

### 第 4 步 · 识别否定词

常见否定词来源：
- **配件词**（买家搜的是配件而非本品）
- **同类不同款**（如搜"手镯"但产品是"手链"）
- **竞品品牌词**（若不打算截流）
- 评论里出现的**误解性搜索**（买家以为产品是别的）

### 第 5 步 · ⛔ P1 闸门：给方案

**不得自行定稿。** 必须把 2–3 个覆盖策略摆出来让用户选，格式见 `references/01-gates.md`。

---

## P1 闸门的方案维度

给方案时要覆盖这四个取舍：

| 维度 | 选项 |
|---|---|
| **覆盖策略** | 激进覆盖（词多面广，预算分散）／ 集中爆破（词少打透，起量快）／ 保守铺量（先小范围验证） |
| **主攻词数量** | 由策略倒推，给出具体数字 |
| **长尾深度** | 覆盖到几词组合 |
| **是否含竞品品牌词** | 涉及法律与平台政策边界，**必须让用户明确决定** |

## 挂接技能

| 技能 | 何时用 | 不可用时 |
|---|---|---|
| `amazon-keyword-strategy` | 有词表时，可做标品/非标品判别 + 词根六分类 | 数据源无关，**上传词表即可运行** |
| `proboost-amazon-keyword-research` | L1 有账号 | 降到 L2 反推 |
| `xiyou-insight` | L1 有账号 | 同上 |

⚠️ `amazon-keyword-strategy` 的价值在于**词表的深加工**（词根分类、PPC 四象限），
它不负责**产生**候选词 —— 候选词得靠本环节的 L2 反推。两者是接力关系。

## 已知局限

1. **无搜索量** → 分层是相对的，不能按真实热度排序；"核心词"是**意图**上的核心，未必是**流量**上的核心
2. **autocomplete 只反映热门搜索** → 低搜索量长尾词抓不到（但长尾恰恰是新品避竞争的地方）
3. **竞品反推的词是"对手的选择"** → 不代表全部机会，可能错过对手也没发现的词
4. **不含广告实测数据** → 哪个词真的能转化，要跑过广告才知道（属环节 09/10）
