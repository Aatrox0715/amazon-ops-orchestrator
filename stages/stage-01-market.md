# 环节 01 · 类目与市场调研

**闸门**：🟢 P2（自动放行，做完汇报即可）
**目录**：`projects/<代号>/01-市场调研/`
**上游**：无
**下游**：02 竞品拆解、05 定价与利润测算

---

## 目标

回答一个判断：**这个类目值不值得进，以什么姿态进。**

不追求数据最全。追求**在现有数据条件下结论站得住**——每个判断都能说清依据和置信度。

---

## 输入要求

| 输入 | 必需 | 缺失时怎么办 |
|---|---|---|
| 类目名 / 核心关键词 | 是 | 追问，不能瞎猜 |
| 目标站点 | 是 | 默认 US，但必须跟用户确认 |
| 参考 ASIN（可选） | 否 | 无则从类目榜单反推 |
| 预算量级（可选） | 否 | 标 L3，不参与测算 |

## 执行步骤

### 第 1 步 · 界定类目边界

不能直接拿用户给的关键词去搜。先确认三件事：

- **类目节点**：对应哪个 Amazon browsing node（越具体越好）
- **站点**：不同站点竞争格局差异巨大，不能混用
- **边界**：哪些算同类、哪些不算（这一步决定了后面所有数据的可比性）

**产出**：一段 3–5 行的类目定义，写进 report.md 开头。用户如果不同意这个边界，后面全部白做——所以这一步的结果要在 report 里显眼位置。

### 第 2 步 · 需求侧

| 要看的 | 怎么看 | 拿不到时 |
|---|---|---|
| 市场规模 | 类目 Top 卖家销量总和 / 工具数据 | L3 → 改用相对热度分级（A/B/C） |
| 搜索量趋势 | 关键词工具 / 前台搜索建议 | L3 → 标注 |
| 季节性 | 工具历史曲线 / 类目 BSR 波动 | L3 → 标注"未验证季节性" |
| 需求稳定性 | 看是否依赖单一爆款 | 可从评论数分布推断 |

**分级标准**（L3 降级时用）：

- **A 档**：多个头部 listing 评论数 >5000，类目有明显持续需求
- **B 档**：头部评论数 500–5000
- **C 档**：头部评论数 <500，或类目整体很新

⚠️ 这**不是**搜索量，是相对热度。报告里必须写清区别。

### 第 3 步 · 竞争格局

- **品牌集中度**：Top 10 里品牌数量 / 是否被少数品牌垄断
  - 判断标准：Top 10 中同品牌占比 >50% → 高集中，新卖家难切入
- **评论门槛**：头部 listing 平均评论数 → 决定新品起量的难度
- **卖家类型**：是品牌商、贸易商还是铺货卖家（看 listing 质量与品牌备案痕迹）
- **新卖家活跃度**：近 6 个月上架的 listing 有没有进 Top 100 → 判断"新人还有没有机会"
- **价格带分布**：各价格区间分布占比

### 第 4 步 · 价格带机会

找出**竞争最弱但需求不小**的价格区间。判断依据：

- 某价格带 listing 数量少，但里面的 listing 评论数不低 → 有机会
- 某价格带全是低质量 listing → 用品质差异化切入

### 第 5 步 · 给出进入判断

必须给出明确结论，不能只说"情况如下"：

```json
{
  "entry_worth": true,
  "posture": "以 $25-35 价格带、侧重 XX 差异点切入",
  "confidence": "L2",
  "key_risks": ["品牌集中度高，头部有品牌备案壁垒", "季节性明显，需备货节奏配合"],
  "entry_barrier": "中",
  "recommended_for": "有 XX 供应链资源的卖家"
}
```

`confidence` 字段必填——告诉用户这个判断有多大把握。

## 已知局限

1. **L3 降级下的容量判断是相对值**，不能用于精确的备货量计算
2. **季节性需要至少 12 个月数据**，公开渠道通常拿不到，未验证就必须标注未验证
3. **新卖家活跃度**的判断依赖上架时间字段，部分抓取渠道拿不到，此时标 L3
