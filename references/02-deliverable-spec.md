# 交付物格式规范

## 三件套

每完成一环，落盘到 `projects/<代号>/<环节目录>/`：

```
projects/<产品代号>/
  _state.json                     项目总状态
  01-市场调研/
    output.json                   ← 唯一数据通道，下游只读这个
    report.md                     ← 给人看
    data.xlsx                     ← 数据密集型环节才有
  02-竞品拆解/
  ...
  portfolio/                      作品集汇总输出
```

## output.json 通用结构

所有环节的 `output.json` 共享以下外壳字段：

```json
{
  "stage": "01",
  "stage_name": "类目与市场调研",
  "project": "产品代号",
  "generated_at": "2026-09-20T10:30:00+08:00",
  "data_source_level": "L2",
  "sources": [
    { "field": "category_size", "level": "L2",
      "origin": "竞品 listing 页抓取",
      "verified_at": "2026-09-20" }
  ],
  "missing_fields": [
    { "field": "monthly_search_volume", "level": "L3",
      "reason": "无数据源，且未提供词表",
      "degraded_to": "相对热度分级（非绝对搜索量）" }
  ],
  "confirmed_by_user": [
    { "decision": "主攻价格带选 $25-35", "at": "2026-09-20T11:00:00+08:00" }
  ],
  "payload": { }
}
```

**三个字段不能省**：

| 字段 | 作用 |
|---|---|
| `data_source_level` | 本环的整体数据源级别，让下游知道精度 |
| `missing_fields` | 显式声明缺什么，这是"不编造"的工程保证 |
| `confirmed_by_user` | 哪些结论是用户拍过板的，下游可直接信任 |

`payload` 放该环节的特有数据，字段定义见各 `stages/stage-XX-*.md`。

## report.md 结构

```markdown
# <环节名> · <产品代号>

> 数据源级别：L2 ｜ 生成 2026-09-20 ｜ 上游输入：无

## 结论摘要

1. <结论一> · 来源 · 核实 2026-09
2. <结论二> · 来源 · 核实 2026-08
3. <结论三>

## <分节内容>

...

## 数据缺口（L3）

| 字段 | 缺什么 | 影响 | 降级方式 |
|---|---|---|---|
| 月搜索量 | 无数据源 | 无法做绝对容量判断 | 改用相对热度分级 |

## 下一步

建议进入 <下一环节>，需要你先定 <需要决策的点>。
```

**格式要求**：

- 每条事实性数字后面跟来源与核实日期
- 缺失数据用表格显式列出，不用"暂缺""待补充"这类模糊说法替代
- L3 降级必须在正文对应位置也标注一次，不能只写在末尾

## data.xlsx 使用场景

仅在数据密集型环节生成：

| 环节 | xlsx 内容 |
|---|---|
| 01 市场调研 | 价格带分布、竞品矩阵 |
| 02 竞品拆解 | 竞品对比表 |
| 04 关键词库 | 分层词表（主攻/长尾/否定/品牌） |
| 05 定价利润 | 成本拆解与多价位利润测算 |
| 09 广告架构 | 活动结构表 |

**代码写入规范**：用 openpyxl，公式写进去而非只写值（让用户能改参数看变化）。首行冻结、列宽自适应、表头加粗。

## 文件命名

- 环节目录：`01-市场调研`、`02-竞品拆解`（两位数 + 短名）
- 文件名固定：`output.json` / `report.md` / `data.xlsx`
- 修订版本：改稿不覆盖，写 `report.v2.md`，原版保留

## 落盘后必做

1. 更新 `_state.json`：环节状态、完成时间、产出物路径
2. 若是闸门节点，记录用户决策到 `confirmed_by_user`
3. 若是迭代，追加到 `revision_history`
