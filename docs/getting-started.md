# 起步指引

> 第一次使用这套技能，读这一篇就够。

---

## 一、它是什么

**流程调度器**，不是知识库。

它做四件事：
1. 听懂你要什么，判断该走哪一环
2. 按环节定义把活干了，产出结构化交付物
3. 在应该停的时候停下，等你拍板
4. 把成果落盘成档案，下一步能直接接上

**它不做的**：不替你决策、不编造数据、不跳过确认闸门。

---

## 二、你的任务属于哪一类

先分清这个，**因为可行性差别很大**：

| 任务类型 | 你要给什么 | 能做到什么 | 需要登录吗 |
|---|---|---|---|
| **A · 竞品分析** | 一个竞品 ASIN（最好 3 个） | ✅ **完整**：listing 拆解 → 评论 VOC → 词库反推 → 文案建议 → 合规体检 | ❌ 不需要 |
| **B · 选品判断** | 类目名或关键词 | ⚠️ **半成品**：能给价格带、竞争格局、评论门槛；**给不了市场规模与搜索量**（需工具账号） | ❌ 不需要 |
| **C · 读自己店铺后台** | 卖家账户 | 销量 / 转化 / ACoS / 搜索词 | ✅ 卖家账户 + 每次登录 |
| **D · 抓别人产品评论正文** | 买家账户 | 评论专页正文 | ✅ 买家账户 |

**最常用的入口是 A** —— 它现在就能给出完整质量的结果。

## 三、五分钟上手

```
你：帮我拆一下这个竞品 B0XXXXXXXX
    ↓
我：声明本次计划（做哪一环、要什么输入、产出什么、在哪停）
    ↓
我：开始执行
    ↓
遇到闸门 → 我把方案摆出来，你选一个
    ↓
产出落盘 → projects/<代号>/<环节>/ 下的三件套
```

**你不需要记技能名，也不需要记环节编号。** 直接说需求即可。

---

## 四、跑之前先做三件事

### 1. 检查外部依赖时效

```bash
python scripts/dep_check.py
```

本技能的费率与规范口径依赖 `amazon-coach` 的闪卡。**费率卡会过期** ——
过期后若不主动复核，会**静默使用旧费率**（与"币种读错"同性质：看不出来，但结论会错）。

### 2. 确认数据源级别

| 级别 | 条件 | 影响 |
|---|---|---|
| L1 | 有授权账号 / 卖家后台 | 字段完整 |
| L2 | 无账号，公开可获取 | 抓取 / 反推（**多数量化值会缺**） |
| L3 | 完全拿不到 | 显式标注，不编造 |

### 3. 想清楚要提供什么

**给的信息越具体，L3 缺口越少。** 例如：
- 只说"帮我分析这个类目" → 我只能抓公开数据
- 给出"我关注的 3 个 ASIN + 我的成本结构" → 能做对比与利润测算

## 五、交付物在哪

```
projects/<产品代号>/
  _state.json          进度 / 已确认决策 / 缺口清单
  <环节目录>/
    output.json        ← 下游环节读这个（唯一数据通道）
    report.md          ← 给人看的
    data.xlsx          ← 给表用的
    raw/               ← 原始证据（抓取页面等）
```

**三件套各有用途**，不是重复：
- `output.json` 供下一环消费 —— 所以你改上游，下游能自动接上
- `report.md` 供人阅读
- `data.xlsx` 供直接使用

## 六、跑完先自查

**两层都要跑，缺一不可**：

```bash
python scripts/selfcheck.py <代号>      # 文件层：三件套 / 契约 / 表格有效性
python scripts/crosscheck.py <代号>     # 内容层：跨环节一致性 / 引用链 / 闭环
python scripts/semantic_check.py <代号> # 基数层：币种 / 单位 / 假设标注
python scripts/report_check.py <代号>   # 报数一致：报告是否残留作废值
```

**为什么分这么多层**：实战中曾发生 —— 文件层与内容层**全部通过**，但售价币种读错没被抓到，
因为所有环节用的是同一个错数字（**内部自洽**）。

> **自洽 ≠ 正确。一致性检查发现不了「共同的错误前提」。**
> 所以基数级校验（币种/单位/量纲）必须单独设关卡。

## 七、常见问题

**Q：为什么老是停下来问我？**
A：那是**闸门设计**。高风险环节（P1）会停下给方案让你选。若你明确说"一路跑完别问我"，
P1 可自动推进（我会标注哪些是我替你做的决定），但 **P0（花钱/对外/不可逆）仍然必停**。

**Q：数据拿不到怎么办？**
A：会**显式标注为 L3**（缺什么、为什么缺、用什么降级方案），不会用估算值填。

**Q：能一次分析多个 ASIN 吗？**
A：暂不支持批量，需逐个跑。（已在 `docs/roadmap.md` 的 P2-9 列出）

**Q：能换到别的 agent 上用吗？**
A：可以。本技能遵循通用 Agent Skill 结构（`SKILL.md` + `scripts/` + `references/`），
可直接复制到其他 agent 的 skills 目录，**零配置即可运行**。
详见 `docs/exporting.md`。

**Q：需要先装 amazon-coach 才能用吗？**
A：不需要。自带 `data/min-cards.json`（20 张必需卡）可开箱跑通；
配置外部知识库后自动切换到完整版（141 张卡 + 时效管理）。
用 `python scripts/state.py roots` 可查看当前生效的是哪一个。

**Q：能自己改吗？**
A：可以。环节定义在 `stages/`、规则在 `references/`、脚本在 `scripts/`，都是纯文本。
改完记得更新 `CHANGELOG.md`。
